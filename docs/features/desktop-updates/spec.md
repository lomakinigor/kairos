# Spec: Kairos 1.1.0 — масштабирование, чистый автозапуск и автообновления

## Problem statement

Сделать обновление Kairos понятным и почти автоматическим, удалить старый dev-автозапуск Electron и масштабировать текст без увеличения исходной площади виджета.

## User stories

- Как пользователь, я меняю размер часов колесом мыши и вижу пропорционально изменившийся текст.
- Как пользователь Windows, я вхожу в систему и вижу только Kairos, без окна с логотипом Electron.
- Как внешний пользователь, я получаю новую версию без повторного поиска установщика.
- Как пользователь после обновления, я один раз вижу список новых функций и ограничений.

## Update flow

1. Через 30 секунд после запуска и затем каждые 6 часов приложение проверяет публичный GitHub Release.
2. Доступная версия скачивается в фоне.
3. После скачивания открывается компактное окно Kairos: версия, основные изменения, кнопки «Перезапустить и обновить» и «Позже».
4. При согласии вызывается `quitAndInstall()`.
5. При первом запуске новой версии один раз показывается «Что нового»; просмотренная версия сохраняется в `userData/update-state.json`.
6. Ошибка сети не мешает запуску виджета и не показывает техническое сообщение.

## Release notes 1.1.0

- Перевод с русского на английский и обратно с автоматическим определением языка.
- Простые объяснения IT-терминов с понятными примерами.
- Для обычного пользователя перевод и объяснение терминов ограничены пятью запросами в день.
- Масштабируемый текст виджета.
- Исправлен автозапуск: больше не должно появляться отдельное окно Electron.
- Добавлены автоматические обновления Kairos.

## Startup migration

- Packaged-приложение регистрирует только `process.execPath` Kairos.
- При первом запуске 1.1.0 выполняется точечная очистка устаревших Run values/Startup shortcuts, только если команда содержит Electron и путь проекта Kairos.
- Dev-сборка никогда не включает autostart.
- Проверка обновлений запускается после появления основного виджета и не создаёт окно Electron.

## Text scaling

- `canvasSize` остаётся единым источником масштаба.
- Renderer выставляет CSS custom property с коэффициентом относительно 120 px.
- Масштабируются brand, dial labels, notification text и close button с min/max clamp.
- Базовый размер окна при `canvasSize=120` не меняется.

## UI: «Что нового»

- Стиль существующего Kairos: графитовый фон, янтарный акцент, Segoe UI.
- Окно примерно 460 × 520, без изменения основного виджета.
- Заголовок «Kairos обновлён» и версия.
- Короткий список изменений; ограничение выделено отдельной спокойной плашкой: «Перевод и IT-термины: 5 запросов в день».
- Одна основная кнопка «Понятно».

## Affected modules

- `main.js` — updater state machine, startup migration, changelog window.
- `renderer/app.js`, `renderer/style.css` — text scale variable.
- `updates/` — локальные release notes и UI.
- `package.json` — version/build scripts.
- `test/` — startup, scaling и update-state tests.

## Data/state changes

- Новый `%APPDATA%/kairos/update-state.json`: `{ "lastSeenVersion": "1.1.0" }`.
- Существующие пользовательские файлы не мигрируют и не удаляются.

## Acceptance criteria

- При размере 50–260 px текст пропорционально масштабируется и не обрезается.
- Базовые width/height виджета при 120 px не увеличены.
- Dev Electron не регистрируется в автозапуске.
- Точечная migration не удаляет посторонние startup entries.
- Update errors не мешают запуску.
- Downloaded update не устанавливается принудительно во время работы.
- Release notes 1.1.0 показываются ровно один раз после обновления.
- В release notes явно написано «5 запросов в день».
- Все данные пользователя сохраняются после обновления.

## Negative scenarios and edge cases

- Нет интернета/GitHub недоступен — виджет работает как обычно.
- Пользователь нажал «Позже» — приложение продолжает работу, обновление можно установить при следующем запуске.
- Повторное открытие той же версии — changelog не показывается.
- Свежая установка 1.1.0 — changelog показывается один раз как знакомство с возможностями.
- Несовпадающая чужая Electron startup entry — не трогается.

## Test plan

- Unit: вычисление text scale и clamp.
- Unit: решение о показе release notes по версиям.
- Unit: фильтр безопасного удаления старой startup entry.
- Integration: updater events → UI state без реальной публикации.
- Build verification: NSIS artifacts включают `latest.yml` и `.blockmap`.
- Manual: автозапуск Windows, update 1.0.5 → 1.1.0, сохранность userData.

## Rollback

- Откатить GitHub Release из latest либо выпустить patch 1.1.1.
- Update state является необязательным; его отсутствие безопасно.
- Startup migration одноразовая и ограничена точным совпадением Kairos/Electron.
