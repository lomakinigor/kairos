# UX-аудит Kairos 1.1.0

Дата: 2026-08-03
Формат: code-based audit + unit/integration/build verification.

## Итоговый скор

| Принцип | Результат | Порог | Статус |
|---|---:|---:|---|
| Дизайн | 88% | 70% | ✅ |
| Удобство | 90% | 80% | ✅ |
| Выгода | 89% | 75% | ✅ |

Вердикт: **ГОТОВО К ПИЛОТНОМУ РЕЛИЗУ** после публикации GitHub Release.

## Дизайн — 21/24

- Визуальная иерархия 3/3: версия, изменения, лимит и CTA читаются в правильном порядке.
- Соответствие Kairos 3/3: сохранены графитовый фон и янтарный акцент.
- Типографика 2/3: Segoe UI надёжен офлайн, но не создаёт уникальную пару.
- Цвет и контраст 3/3.
- Spacing и сетка 3/3.
- Interactive states 3/3: hover, active, focus-visible.
- Доступность 2/3: semantic HTML и reduced motion есть; нужен ручной тест screen reader.
- Целостность 2/3: окно рассчитано на 460 × 520; нужен render-check на реальной сборке.

## Удобство — 27/30

- Проверка обновлений отложена на 30 секунд и не мешает запуску.
- Обновление скачивается в фоне, принудительный restart отсутствует.
- «Позже» сохраняет текущую работу.
- Release notes показываются один раз на версию.
- Ошибки сети остаются тихими.
- Лимит сформулирован однозначно: 5 запросов в день.
- Состояние обновления хранится отдельно от пользовательских данных.
- Снижение: нет отдельной кнопки ручной проверки обновлений в настройках.

## Выгода — 24/27

- Стороннему пользователю не требуется искать новый установщик.
- Напоминания и настройки сохраняются.
- Пользователь сразу понимает новые возможности и ограничения.
- Text scaling повышает читаемость.
- Исправлен раздражающий dev-startup Electron.
- Снижение: неподписанный installer может вызвать SmartScreen при первой установке.

## После релиза

1. Добавить «Проверить обновления» в настройки.
2. Провести ручной update 1.0.5 → 1.1.0 на второй Windows-учётной записи.
3. Рассмотреть code-signing certificate при росте внешней аудитории.
